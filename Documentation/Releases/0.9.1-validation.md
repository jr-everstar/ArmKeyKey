# 0.9.1 build 18 validation

The reported 0.9.0 installation failure was confirmed in `/var/log/install.log`: `PKInstallErrorDomain Code=112` from preinstall's running-process guard. During UI investigation the original app exited and a new process appeared. The automation's state read may itself have reopened the app; that observation does not establish which macOS subsystem originally caused the user's relaunch.

The fix removes dependence on process absence. `pkgbuild` documents that `BundleOverwriteAction=upgrade` atomically replaces the bundle; this setting and `RequireLogout` remain enforced. A backup is copied before replacement, without moving the shared bundle away or modifying its executable.

Eleven isolated installer tests cover running-process upgrades, shared-bundle backup without inode changes, symlink rejection, personal migration, repeated installs and learning-data preservation. No test kills a real input method or installs into the live system. Local updater regression tests and Release build are also run. Manual cross-account/login acceptance is not claimed.
